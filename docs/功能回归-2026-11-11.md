## 二、发现的问题

### 已修（本次提交 d2f8e13）

**P1 · 自然语言解析「点半」错误（功能 bug）**
输入「晚上8点半 复盘」，时间是 `20:00` 而不是 `20:30`，并且「半」被留在任务内容里，任务名变成「半 复盘」。
原因：时间正则 `(\d{1,2})[:：点时](\d{1,2})?分?` 只认数字分钟。
修法：分钟位接受「半」并映射为 30。验证：`晚上8点半 → 20:30`、`8点30 → 08:30`、`8:15 → 08:15` 均正确，内容不再残留。

**P2 · 切换日报风格后立即生成，仍是旧风格（时序 bug）**
日报风格（纯文本 / Markdown）由后端读**磁盘上的** `settings.json` 决定，而设置写盘有 300ms 防抖。
在设置里切到 Markdown 后马上点「生成」，草稿仍是纯文本。
修法：`generateReportContent()` 生成前先 `await saveSettings(State.settings)`。
验证：只改内存设置、立刻生成，已能拿到 Markdown 格式；改回纯文本同样即时生效。

### 未修，建议排期

**P3 · 中文表头 CSV 导入静默得到 0 条**
导入器按**英文字段名**匹配表头（`content,date,priority,...`，与导出的 CSV 一致）。
用户手工用「任务内容,截止日期…」这类中文表头造的文件，解析结果是 0 条，提示只有「文件中未解析到任务」，没有任何「表头列名不被识别」的说明。
建议：表头不认识时给出明确提示（列出期望列名），或兼容一组中文列名别名。

### 观测项（当前行为，未必是 bug）

**P4 · 自动提权对「低」只升一级**
`runAutomations()` 里低→中、中→高，但同一任务升过一次后 `_promoted=true` 不再升，
所以低优先级任务临近到期只会变成「中」，不会自动到「高」。若本意就是「只提一级」则符合预期。

**P5 · 日报/导出等取的是磁盘数据**
`generate_report` 读 `todoList.json`，而前端落盘有 400ms 防抖。
极端情况下「刚勾完任务立刻点日报」可能少一条刚变更的记录。实际点击耗时通常已超过防抖窗口，未复现。

**P6 · 图表空态**
「效率分析」在没有任何「有开始时间且已完成」的任务时只显示一行提示文字，没有图形占位。
当前真实数据能满足，属边界展示，未改。
