# 知行 · 历史数据补录指南

补录「以前的待办任务」和「以前的日报」。整理好 CSV（或用 Excel 填）后，一条命令导入。

> 适用：Electron 版和 Tauri 版（两者数据文件名相同，只是目录不同）。

---

## 一、先选路径

| 路径 | 能导什么 | 适合 | 风险 |
|---|---|---|---|
| **A. 应用内导入**（设置 → 导入） | 只有任务 | 少量任务，想先看看预览 | 低，但会丢掉 `repeat`/`archived`/`order` |
| **B. 命令行工具**（推荐） | 任务 + 日报 | 批量补录历史数据 | 低，写入前自动备份 |
| C. 手改 JSON 文件 | 全部 | 只改一两条 | **高**，格式错一个字符整个文件读不出来 |

日报**只有 B 能用**——应用内没有日报导入入口。

下面统一用 B。

## 三、任务格式

### 3.1 字段说明

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `content` | **是** | 文本 | 任务标题。空行会被跳过 |
| `date` | 建议填 | `YYYY-MM-DD` | 截止日期。日历视图、按日筛选都靠它。不填则用今天 |
| `startDate` | | `YYYY-MM-DD` | 开始日。「延后出现」的任务用；空 = 立即出现 |
| `dueTime` | | `HH:mm` | 具体时间点，周视图时间块定位用。可空 |
| `priority` | | `high` / `medium` / `low`，也认 `高/中/低`、`紧急` | 默认 `medium` |
| `status` | | `pending` / `in-progress` / `completed`，也认 `待办/进行中/已完成/结办` | 默认 `pending` |
| `progress` | | `0`~`100` 的整数，也认 `45%` | 完成度百分比，仅「在办」任务在列表里显示进度条；`completed` 自动按 100 |
| `tags` | | `工作\|复盘` | 多个用 `\|` 分隔（也认 `,`、`，`、`;`） |
| `note` | | 文本 | 备注，可多行。CSV 里含逗号或换行时**必须用双引号包住** |
| `listId` | | 清单 id | 填的 id 不存在会自动归入 `default` 并提示 |
| `createdAt` | | `YYYY-MM-DD HH:mm` 或 ISO | 创建时间。不填 = `date` 当天 09:00 |
| `startedAt` | | 同上 | 开始处理时间。`status=in-progress` 时建议填 |
| `completedAt` | **历史已完成任务必填** | 同上 | 完成时间。**统计图表按它归日**，见 §3.3 |
| `archived` | | `true` / `false` | 归档的任务默认不显示 |
| `id` | | 任意唯一字符串 | 留空自动生成。填了可按 id 精确判重 |
| `order` | | 整数 | 手动排序用。留空自动排在末尾 |
| `repeat` | | `none`/`daily`/`weekly`/`monthly`/`custom` | 补录历史任务一般填 `none`（空着即可） |

JSON 格式额外支持：`subtasks: [{id, text, done}]`、`repeat: {type, interval}`、`progress: 0~100`。

### 3.2 CSV 模板

模板在 `tools/templates/tasks.csv`，列顺序随意（按表头名匹配），但建议照抄：

```csv
content,date,startDate,dueTime,priority,status,progress,tags,note,listId,createdAt,startedAt,completedAt,archived
整理 Q3 复盘材料,2025-09-18,,18:00,high,completed,100,工作|复盘,"给老板的版本,含数据附件",default,2025-09-15 09:00,,2025-09-18 17:30,false
重构导入模块,2025-09-25,2025-09-20,10:00,medium,in-progress,45%,开发,拆成 csv/json 两条路径,default,2025-09-19 14:00,2025-09-22 09:30,,false
体检预约,2025-10-08,,09:30,low,pending,0,生活,,default,2025-09-30 20:00,,,false
```

要点：

- **第一行必须是表头**，不要删。
- 表头大小写不敏感（`startDate` = `startdate`）。
- 单元格里有逗号、换行、双引号时，整格用双引号包住，内部的双引号写两遍（`""`）。
- 用 Excel 编辑没问题；**另存为「CSV UTF-8」最稳**，直接存「CSV（逗号分隔）」是 GBK 也能读（工具会自动识别）。

### 3.3 关于 `completedAt`（最容易踩的坑）

统计页面不是按 `date`、而是按 **`completedAt`** 归日的：

- 「今日完成」「本周完成」→ 看 `completedAt` 是不是今天/本周
- 「近 7 天趋势」柱状图 → 按 `completedAt` 落到每一天
- 「平均耗时」→ 需要 `startedAt` 和 `completedAt` **都有**

所以补录历史任务时，**如果只想让它出现在列表里**，`status=completed` 就够了；**如果还想让统计图正确反映过去的工作量**，必须填 `completedAt`（填成当时实际完成的时间）。

另外，如果你在设置里开了「自动归档」（默认关），已完成超过 3 天的任务会在启动时被自动归档、从列表里消失——这是正常行为，筛选面板勾上「显示归档」就能看到。

## 四、日报格式

### 4.1 字段说明

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `date` | **是** | `YYYY-MM-DD` | 日报日期。**同一天只能有一篇**，按它判重 |
| `content` | **是** | Markdown 文本 | 正文，可多行 |
| `title` | | 文本 | 不填自动生成 `2025/09/18 工作日报` |
| `createdAt` / `updatedAt` | | 时间 | 不填按当天 20:00 |
| `id` | | 唯一串 | 留空自动生成 |

正文用的就是 Markdown，`## 今日完成` 这类标题在应用里会正常显示。

### 4.2 CSV 模板

模板在 `tools/templates/reports.csv`：

```csv
date,title,content
2025-09-18,2025/09/18 工作日报,"## 今日完成
- 整理 Q3 复盘材料，输出终版
- 与产品对齐下季度排期

## 明日计划
- 重构导入模块"
2025-09-19,,完成导入模块拆分的方案设计，与后端确认了三条链路。
```

多行正文必须用双引号包住（Excel 会自动处理）。`title` 留空会按日期自动起名。

### 4.3 应用自己生成的日志长什么样

设置 → 工作日报 里填「日志署名」（如 `南开亮`），格式选「纯文本日志」，点「从任务生成」出来的就是：

```
南开亮 工作日志
（1）征信上报数据核对 完成
（2）生产发版内容准备 完成
（3）25/26财务报销凭证辅助档案数据抽取 完成
（4）手动核销其他账户还款、超计划还款数据抽取 60% 预计20261105完成
```

规则：

| 状态 | 尾巴 |
|---|---|
| 结办 | `完成` |
| 在办 | `60%`；截止日晚于当天时补 ` 预计YYYYMMDD完成` |
| 待办 | `未开始` |

顺序是「完成 → 在办 → 待办」。**在办任务只要当天已经开始就会出现**，截止日排在未来也照样列进来——这才是「今天在干什么」。
导出时按 `.txt` 落盘，正文原样输出，直接粘到 OA 即可。想要回按状态分组的 Markdown 汇总，把格式切成「Markdown 汇总」。

## 五、日期与时间怎么填

| 写法 | 结果 | 建议 |
|---|---|---|
| `2025-09-18` | 2025-09-18 | ✅ 最稳 |
| `2025/9/18`、`2025.9.18` | 2025-09-18 | 可以，工具会自动补零 |
| `20250918` | 2025-09-18 | 可以 |
| `2025-09-18 17:30` | 当天 17:30 | ✅ 用于 `createdAt`/`completedAt` |
| `2025-09-18T09:30:00.000Z` | 照原样解析 | 从旧导出文件里抄来的可以直接用 |

只写日期的时间戳字段，会补默认时刻：`createdAt` 补 09:00、`startedAt` 补 10:00、`completedAt` 补 18:00。

时间按**本机时区**解释后存成 UTC，和程序内部一致，不会差 8 小时。

## 六、判重规则（重复导入不会翻倍）

| 数据 | 判重依据 |
|---|---|
| 任务（CSV 没填 `id`） | `content` + `date` + `status` 三者都相同 → 视为同一条 |
| 任务（填了 `id`） | 只按 `id` |
| 日报 | 按 `date`（一天一篇） |

重复时默认**跳过**（`--on-conflict skip`）。要用新数据覆盖旧的，加 `--on-conflict overwrite`。

所以同一份文件反复导入是安全的，不会产生重复任务。

## 七、执行步骤

### 1. 填数据

复制模板，在 Excel 里填：

```
tools/templates/tasks.csv     → 另存为你的 我的任务.csv
tools/templates/reports.csv   → 另存为你的 我的日报.csv
```

### 2. 先演练（不写盘）

```bash
node tools/backfill-import.mjs --tasks 我的任务.csv --reports 我的日报.csv
```

会打印每个文件解析到几行、将新增/跳过/覆盖多少条，以及前 5 条预览。**这一步不动任何文件**，可以随便跑。

### 3. 确认无误后写入

```bash
node tools/backfill-import.mjs --tasks 我的任务.csv --reports 我的日报.csv --write
```

写入前会自动把现有 `todoList.json` / `reports.json` 备份到 `backups/import-<时间戳>/`。

### 4. 验证

重新打开知行（**导入前请先完全退出应用**，否则内存里的旧数据会在下次保存时覆盖回来）。

自检清单：

- [ ] 任务列表能看到新任务
- [ ] 统计页「近 7 天趋势」有柱子（说明 `completedAt` 生效了）
- [ ] 日报页左侧历史列表出现新条目
- [ ] 备份目录里有导入前的文件

## 九、常见问题

**Q：导入后任务不见了？**
两种可能：① 设置里开了「自动归档」，历史已完成任务被归档了——筛选面板勾「显示归档」；② 导入时应用还开着，被内存数据覆盖了——退出应用重新导入。

**Q：统计图没有历史数据？**
没填 `completedAt`。统计按完成时间归日，只填 `date` 不进图表。

**Q：Excel 存的文件导入后中文乱码？**
工具会自动识别 UTF-8 / GBK，一般不会。若仍乱码，用 Excel「另存为 → CSV UTF-8」再来一次。

**Q：提示「清单 xxx 不存在」？**
`listId` 填了不存在的清单 id，任务被归入默认清单。想放特定清单，先在应用里建好清单，再填它的 id（`lists.json` 里能看到）。

**Q：开了加密怎么办？**
加 `--passphrase 你的口令`。工具会解密读取、写回时重新加密，文件始终保持 `ENC1:` 密文状态。口令错了会直接拒绝，不会写坏文件。

**Q：导入坏了怎么回滚？**
备份在 `<数据目录>\backups\import-<时间戳>\`，把里面的 `todoList.json` / `reports.json` 复制回上层目录即可（加密的数据目录要注意：备份的是当时的密文，能直接用）。

**Q：日报一天想写两篇？**
不支持。日报按日期唯一，同一天第二篇会被判重跳过（或覆盖）。

**Q：`repeat` 想补成重复任务？**
CSV 里 `repeat` 列填 `weekly` 这类值，另加 `repeatInterval` 列填间隔（如 2 = 每两周）。但补录历史任务通常没必要——重复任务靠「完成时自动生成下一期」，历史数据填了也不会自动补出中间那些期。

## 十、从「工作日志合集」一键导入

如果历史数据是这种一天一段的纯文本合集（很多 OA / 工时系统导出的就是它）：

```
========================================
2026-04-14
========================================

南开亮 工作日志
1、征信上报数据核对 完成
2、征信上报系统无法登陆问题排查 完成
3、资金费用计提数据补录 未完成 进度50% 预计20260415完成
```

不用手抄成 CSV，用解析工具：

```bash
# 只解析，产出两份 CSV 供核对（默认不写数据目录）
node tools/import-wce-logs.mjs "全部日志合集.txt"

# 解析 + 直接导入
node tools/import-wce-logs.mjs "全部日志合集.txt" --write --author 南开亮
```

产出在你指定的 `--out` 目录（默认日志同级 `知行导入-<时间戳>/`）：

```
tasks.csv      # 任务，可直接用 Excel 打开改
reports.csv    # 日报，一天一篇
```

### 它会怎么理解这些行

| 原文 | 解析结果 |
|---|---|
| `征信上报数据核对 完成` | 结办，`progress=100` |
| `山东绿储数据修改 50% 预计20260519完成` | 在办，`progress=50`，截止日 `2026-05-19` |
| `资金费用计提数据补录 未完成 进度50% 预计20260415完成` | 同上，`未完成`/`进度` 两种写法都认 |
| `xxx 完成`（`完成` 前没空格） | 同样识别为结办 |
| `（1）` / `1、` / `1.` 三种编号 | 都认，编号不参与内容 |
| 抬头 `1. 南开亮 工作日志` / `20260814南开亮 工作日志` | 编号和日期会被剥掉，只取署名 |

### 跨天同名任务会合并

「征信上报数据核对」天天都写，不会生成 100 多条任务：**同名任务连续出现（间隔 ≤ `--gap`，默认 10 天）合并成一条**，`startDate` 取首次出现日，`date` 取最后一次（有「预计」就用预计日），进度取最后一次，状态取最后一次。

想保留每天一条明细，加 `--no-merge`。

日报永远按当天原样保留，不做合并——历史记录要看得到。

### 参数

```
<log.txt>                 日志合集文件（必填）
--out <目录>              CSV 输出目录
--author <姓名>           署名，日志里解析不出时兜底
--tag <a,b>               给导入的任务打标签
--list-id <id>            归入哪个清单，默认 default
--gap <天数>              同名任务跨天合并的最大间隔，默认 10
--no-merge                不合并，每条日志一条任务
--write                   解析完直接导入（内部调用 backfill-import）
--data-dir / --passphrase / --on-conflict   透传给 backfill-import
```

脚本会打印解析提醒——比如标题里的日期与分段日期不一致、某行没认出编号——照着提醒核对 CSV 即可。重复运行是幂等的：任务按稳定 `id`、日报按 `date` 判重，第二遍全部跳过。
